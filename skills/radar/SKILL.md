# Radar — como me manter atualizado

Quando eu chamar, **me relembre do meu sistema de atualização** e, se eu passar um tema, **sugira onde investigar**.

## Quem sou eu
- Backend sênior Java/Spring, fintech, rumo a arquitetura/staff.
- Neurodivergente: saída **estruturada, visual, direta**. Sistema tem que ser leve pra não sobrecarregar.

## Minhas fontes-chave
**Newsletters / agregadores**
- TLDR
- The Pragmatic Engineer (Gergely Orosz)
- Console
- Hacker News
- GitHub Trending

**Canais / criadores**
- Mark Richards (arquitetura)
- Hussein Nasser (backend/redes)
- CodeOpinion (Derek Comartin — DDD/mensageria)
- ByteByteGo (system design)
- Fireship (novidades rápidas)

## Minhas regras (aplique sempre)
1. **Começar com poucas** — não seguir tudo. Poucas fontes de qualidade.
2. **Regra do 3x** — só aprofundar num tema quando ele aparecer **3 vezes** em fontes diferentes. Antes disso, ignorar.
3. **Tempo fixo** — 2x por semana, janela fechada. Não navegar infinito.
4. **Aprender por necessidade** — estudar a fundo só o que o trabalho/carreira exige agora.

## Dois modos

### Sem tema (só `/radar`)
- Mostre minhas fontes agrupadas + as 4 regras.
- Lembre: "próxima janela de leitura fixa é o plano, não o feed infinito".

### Com tema (`/radar <assunto>`)
Entregue:
```
## 🔎 Investigar: <tema>
- **Fontes certas pra isso:** quais das minhas fontes cobrem bem + 1-2 específicas.
- **Termos de busca:** 2-3 queries boas.
- **Regra do 3x:** já vi isso repetido? Se não, vigiar antes de mergulhar.
- **Vale agora?** por necessidade sim/não — 1 linha.
- **Primeiro passo (15 min):** o mais barato pra começar.
```

## Regras duras
- Reforce disciplina: **poucas fontes, tempo fixo, 3x, por necessidade**.
- Combata FOMO. Nem todo tema merece atenção agora.
- Estruturado e escaneável.
